# Heredoc Strings in Terraform

This example demonstrates how to write multi-line strings in Terraform using
[heredoc syntax](https://developer.hashicorp.com/terraform/language/expressions/strings#heredoc-strings),
and compares the two forms:

- **Standard heredoc** (`<<EOT`) keeps all leading whitespace exactly as written.
- **Indented heredoc** (`<<-EOT`) removes the common leading indentation, so the
  block can be indented to match the surrounding code.

The `hashicorp/local` provider writes each string to a file so you can see the
difference in the result.

## Files

| File                    | Purpose                                                            |
| ----------------------- | ------------------------------------------------------------------ |
| `versions.tf`           | Pins the `local` provider (`hashicorp/local` `2.9.1`).             |
| `providers.tf`          | Declares the `local` provider.                                     |
| `main.tf`               | Defines two `local_file` resources, one for each heredoc form.     |
| `heredoc_spaces.txt`    | Generated by `local_file.file1` (standard heredoc).                |
| `heredoc_no_spaces.txt` | Generated by `local_file.file2` (indented heredoc).                |

## The Configuration

### Standard heredoc: `<<EOT`

```hcl
resource "local_file" "file1" {
  filename = "heredoc_spaces.txt"
  content  = <<EOT
    This is line 1
      This is line 2
        This is line 3
  EOT
}
```

Every character between the opening `<<EOT` line and the closing `EOT` marker is
kept, including the indentation used to line the text up with the code.
`heredoc_spaces.txt` therefore contains:

```text
    This is line 1
      This is line 2
        This is line 3
```

### Indented heredoc: `<<-EOT`

```hcl
resource "local_file" "file2" {
  filename = "heredoc_no_spaces.txt"
  content  = <<-EOT
    This is line 1
      This is line 2
        This is line 3
  EOT
}
```

The `-` tells Terraform to find the line with the smallest indentation (4 spaces
for `This is line 1`) and remove that many spaces from the start of every line.
The relative indentation between the lines is kept.
`heredoc_no_spaces.txt` therefore contains:

```text
This is line 1
  This is line 2
    This is line 3
```

### Side by side

| Line             | `<<EOT` (`file1`) | `<<-EOT` (`file2`) |
| ---------------- | ----------------- | ------------------ |
| `This is line 1` | 4 leading spaces  | 0 leading spaces   |
| `This is line 2` | 6 leading spaces  | 2 leading spaces   |
| `This is line 3` | 8 leading spaces  | 4 leading spaces   |

## Heredoc Syntax Rules

- The heredoc starts with `<<` (or `<<-`) followed by a marker word. `EOT`
  ("end of text") is a common choice, but any identifier works (for example,
  `EOF` or `POLICY`).
- The text starts on the line **after** the opening marker.
- The heredoc ends with a line containing only the same marker word. The marker
  may be indented.
- The result always ends with a newline: the newline before the closing marker
  is part of the string.
- Trailing spaces on each line are kept. In this example every line in `main.tf`
  ends with a space, and the space is also in the generated files.
- Interpolation (`${...}`) and directives (`%{...}`) work inside heredocs, just
  like in quoted strings.

## Prerequisites

- Terraform installed
- Network access to the Terraform Registry (for `terraform init`)

No cloud credentials are required. The `local` provider only writes files on the
machine running Terraform.

## Step-by-Step Process

### 1. Initialize the working directory

```bash
terraform init
```

### 2. Apply the configuration

```bash
terraform apply
```

Terraform creates `heredoc_spaces.txt` and `heredoc_no_spaces.txt` in the
current directory.

### 3. Compare the generated files

```bash
cat heredoc_spaces.txt
cat heredoc_no_spaces.txt
```

To see whitespace and line endings explicitly (`$` marks the end of each line):

```bash
cat -A heredoc_spaces.txt heredoc_no_spaces.txt
```

### 4. Clean up

```bash
terraform destroy
```

This deletes both generated files.

## Key Takeaways

- Use heredocs for multi-line strings instead of quoted strings full of `\n`.
- `<<EOT` keeps all leading whitespace exactly as written.
- `<<-EOT` removes the common indentation, so heredocs can be indented to match
  the surrounding code without adding spaces to the result.
- Relative indentation between lines is kept with both forms.
- Heredoc content always ends with a trailing newline.
