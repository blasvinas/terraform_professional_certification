# String Escape Sequences in Terraform

This example demonstrates how to use **escape sequences** inside Terraform
string literals, using the `hashicorp/local` provider to write a file whose
content includes double quotes.

The scenario: we want to write a sentence that contains quoted names
(`"Alice"` and `"Bob"`) into a file. Because the string itself is delimited by
double quotes, the inner quotes must be escaped.

## Files

| File           | Purpose                                                       |
| -------------- | ------------------------------------------------------------- |
| `versions.tf`  | Pins the Terraform `local` provider (`hashicorp/local` `2.9.1`). |
| `providers.tf` | Declares the `local` provider.                                |
| `main.tf`      | Defines a `local_file` resource whose content uses escapes.   |
| `test.txt`     | The file generated by Terraform after `apply`.                |

## The Configuration

```hcl
resource "local_file" "file" {
  content  = "The name of my best friends are \"Alice\" and \"Bob\""
  filename = "test.txt"
}
```

The `\"` sequences escape the double quotes so they become part of the string
rather than terminating it. The resulting file content is:

```
The name of my best friends are "Alice" and "Bob"
```

## Common Escape Sequences

Terraform strings use backslash (`\`) escape sequences:

| Sequence     | Meaning                                       |
| ------------ | --------------------------------------------- |
| `\"`         | Literal double quote                          |
| `\\`         | Literal backslash                             |
| `\n`         | Newline                                       |
| `\t`         | Tab                                           |
| `\r`         | Carriage return                               |
| `\uNNNN`     | Unicode character (4 hex digits)              |
| `\UNNNNNNNN` | Unicode character (8 hex digits)              |

### Template Escapes

Terraform also interprets `${ ... }` (interpolation) and `%{ ... }` (directives)
inside strings. To include those literally, double the leading symbol:

| Sequence | Meaning                          |
| -------- | -------------------------------- |
| `$${`    | Literal `${` (no interpolation)  |
| `%%{`    | Literal `%{` (no directive)      |

## Prerequisites

- Terraform >= 1.0
- No cloud credentials needed — the `local` provider writes to the local
  filesystem.

## Step-by-Step Process

### 1. Initialize the working directory

```bash
terraform init
```

### 2. Apply the configuration

```bash
terraform apply
```

Terraform creates `test.txt` with the escaped content.

### 3. Verify the output

```bash
cat test.txt
# The name of my best friends are "Alice" and "Bob"
```

## Alternative: Heredoc Strings

For multi-line content or to avoid escaping quotes, you can use a heredoc:

```hcl
resource "local_file" "file" {
  content  = <<-EOT
    The name of my best friends are "Alice" and "Bob"
  EOT
  filename = "test.txt"
}
```

Inside a heredoc, double quotes do not need to be escaped.

## Key Takeaways

- Use `\"` to embed double quotes inside a quoted Terraform string.
- Backslash escapes (`\n`, `\t`, `\\`, etc.) work as in most languages.
- Use `$${` and `%%{` to emit literal `${` and `%{` without triggering
  interpolation or directives.
- Heredoc syntax is a cleaner option for multi-line or quote-heavy content.
