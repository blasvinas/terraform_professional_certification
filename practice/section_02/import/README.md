# Importing Existing AWS Resources with the `import` Block

This example demonstrates how to bring an **existing** AWS resource under
Terraform management using the declarative [`import` block](https://developer.hashicorp.com/terraform/language/import)
(introduced in Terraform 1.5).

The scenario: an AWS Security Group (`sg-099f2df0ec4f58b9c`) already exists in
your account, and you want Terraform to manage it without recreating it.

## Files

| File           | Purpose                                                                       |
| -------------- | ----------------------------------------------------------------------------- |
| `versions.tf`  | Pins the Terraform AWS provider (`hashicorp/aws` `6.64.0`).                    |
| `providers.tf` | Configures the AWS provider to use the `us-east-1` region.                    |
| `main.tf`      | Contains the `import` block that maps the existing SG to a Terraform address. |
| `sg.tf`        | The resource configuration generated by Terraform for the imported SG.        |

## The `import` Block

```hcl
import {
    to = aws_security_group.test_sg
    id = "sg-099f2df0ec4f58b9c"
}
```

- **`to`** — the Terraform resource address that the existing object will be
  bound to (`aws_security_group.test_sg`).
- **`id`** — the provider-specific identifier of the existing resource. For an
  AWS security group this is the security group ID.

Unlike the older `terraform import` CLI command, the `import` block is
**configuration-driven**: it lives in your `.tf` files, is planned like any other
change, and can be reviewed before being applied.

## Prerequisites

- Terraform >= 1.5
- AWS credentials configured (e.g. via `AWS_PROFILE`, environment variables, or
  `~/.aws/credentials`)
- An existing security group whose ID you know

## Step-by-Step Process

### 1. Configure the provider

`providers.tf` and `versions.tf` set up the AWS provider and pin its version.

### 2. Add the `import` block

Declare which existing resource to import and the target address, as shown in
`main.tf`.

### 3. Generate the resource configuration

Instead of writing the resource block by hand, let Terraform generate it for you:

```bash
terraform plan -generate-config-out=sg.tf
```

Terraform reads the `import` block, queries the real resource from AWS, and
writes a matching `resource` block into `sg.tf` (the header comments
`# __generated__ by Terraform` mark the generated content).

> Review the generated file. Some attributes (like read-only or default values)
> may need to be adjusted or removed before applying.

### 4. Apply the import

```bash
terraform apply
```

Terraform imports the resource into state and reconciles the configuration.
The plan should show the resource being **imported** (and no destructive
actions if the configuration matches the real resource).

### 5. Verify

```bash
terraform state list
terraform state show aws_security_group.test_sg
```

You should see `aws_security_group.test_sg` listed and managed in state.

### 6. Clean up (optional)

Once the import is complete, the `import` block has served its purpose and can
be safely removed from `main.tf`. The resource remains managed via `sg.tf`.

```bash
# After removing the import block, confirm nothing changes:
terraform plan
```

## Key Takeaways

- The `import` block is the modern, declarative alternative to the
  `terraform import` CLI command.
- Combined with `-generate-config-out`, it removes the need to hand-write the
  resource configuration.
- `import` blocks are safe to remove after a successful apply; the resource
  stays under Terraform management through its resource block.
- Always review generated configuration before applying to avoid unintended
  changes.
